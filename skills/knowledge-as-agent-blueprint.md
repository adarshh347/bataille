# Skill — The knowledge base as agent-blueprint

*A metaskill plus three reading skills. Established 2026-05-23, lifted from the
collaborator's annotations on `book-on-nietzsche.md`. Framing verified: the
four-layer model.*

## The metaskill
1
Treat the knowledge dossier not as flat reference but as **quarry for a layered
agent-psyche**. The long-term aim of this project is a *future application* — an
agent with a Bataille-derived mind. The knowledge files are the source-rock that
agent gets assembled from. So every fragment carries a second question beyond
"is it true?": **which layer of the agent does it feed?**

## The four-layer model

- **L1 · Genetic** — not facts, *patterns*. The recurring *moves* and *registers*
  of thought: "push a doctrine past the consequence its author drew," "the
  revelatory register," "the concept that betrays itself." The genetic layer is
  what lets the agent *recognize similar things and generate new ones*. The
  generative DNA.
- **L2 · Persona** — the *character*: temperament, obsessions, wounds, voice.
  Who the agent *is*. Bataille-as-person — formed under illness, occupation, the
  fear of madness; a librarian, not a professor; drawn to loss over safety.
- **L3 · Purpose** — the *agentic drive*: what the agent is *for*. Bataille's
  purpose — to be the Nietzsche Nietzsche never dared be, to continue a thought
  past where its author stopped. A mind with a purpose: this is what makes the
  application an *agent* and not a database.
- **L4 · Context** — the *knowledge the agent reasons with*: concepts, book maps,
  the four-phase arc, facts.

Two cross-cutting **tags** (not layers):
- **★ / ★★** — salience (important / very important).
- **⟳** — generative seed: a spot where, *after* the system has matured, we want
  it to generate a new insight — not answered now, queued for later.

## The annotation convention

One line, co-located with the passage it follows, readable and parseable:

`> ⟦layer · ★★ · ⟳⟧ — note, in the collaborator's exploratory register`

Multiple layers allowed (`⟦purpose · persona⟧`) when a fragment genuinely splits.

**Phase note:** annotations live **inline** in the knowledge files for the
current phase. When the project scales / reaches a permanent phase, they move to
a clean sidecar (`blueprint/<file>.md`), leaving the reference prose uncluttered.

## What an annotation does — the four jobs

1. **Route** — send the fragment to a layer (L1–L4).
2. **Rank** — mark salience (★ / ★★).
3. **Seed** — flag for future generation (⟳).
4. **Extract** — when a fragment reveals a reusable *method*, lift it to a skill.

## The three reading skills

How you find what to annotate.

### Read for register, not content
Detect statements whose *force* exceeds their semantic content — that announce
something "for the first time," carry the weight of revelation, express a *will*
rather than report a fact. (Source: Bataille's "Nietzsche expressed, for the
first time, an extreme, unconditional human yearning.") These belong at the
genetic layer: the agent should learn to *recognize this register* and to
*generate in it*. Register is data, not decoration.

### Spot the agentic structure in the source
Read the source for *agent-shaped things*: a mind with a *purpose* that extends
or completes another mind. Bataille-extending-Nietzsche is agent-shaped — it has
intention, a target, a refusal of mere repetition. Route these to the purpose
layer; they are where the future agent gets its drive.

### Generative deferral (seed-marking)
While reading, mark spots where you do *not* want an answer now — you want the
*matured* system to generate a new, sophisticated insight later. Tag them ⟳.
The dossier accumulates a seed-queue; later passes harvest it. This keeps the
reading honest: not every interesting line must be resolved on contact.

## How to apply

When annotating a knowledge file: read it whole; for each load-bearing fragment
run the four jobs; write the annotation **in its layer's native register**
(see `layer-spirit.md`): genetic as a pattern-catalog entry, persona as a
first-person voice fragment, purpose as a manifesto directive, context as a
dry reference entry. Run the swap test on every clause: if its tag could be
replaced by another layer's without breaking, rewrite. Match the density of
the worked template, `knowledge/book-on-nietzsche.md`. Do not over-annotate —
quality over coverage.

## Critical companion skill

**`layer-spirit.md`** — every clause produced under this framework MUST be in
its layer's native register. Uniform-voice annotations (the failure mode of
the first annotation pass) defeat the whole architecture; the differentiation
must be visible on the page, not only in the tag.
